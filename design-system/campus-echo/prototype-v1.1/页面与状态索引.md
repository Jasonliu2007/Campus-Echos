## 流程

- 校园墙 → 发布 → 提交待审 → 我的帖子；同一表单失败时保留输入，提交中禁用。
- 校园墙 → 详情 → 删除确认 → 删除状态。
- 我的 → 内测申请 → 待审批；审批结果和撤销状态分别有独立画面。
- 我的 → 审核队列 → 审核详情 → 确认 → 更新列表；并发已处理不覆盖结果。
- 我的 → 成员管理 → 批准／拒绝／撤销确认。
- 学习资料 → AI点选 → 演示结果；资料、活动未接入的操作统一给说明。
- 设置 → 减弱动态效果、减少透明度，独立开关并保存在原型本机。

## 业务边界

首轮实现文字校园墙及内测、审核；图片、搜索、匿名、编辑、点赞评论、举报后续补原型和业务。真实校园墙无演示数据；本原型的帖子仅作设计样例。学习资料与搭子是明确标注的演示。不会创建订单、支付或加入真实活动。

## 交付质量记录

- 图片均由同一交互HTML导出，非分开手绘。36张逐页状态图。
- 已检查原型主流程、导航、表单状态、减弱动态与画板横向溢出；390×844为主导出尺寸。
- 状态可直接从左侧索引进入，便于开发逐项对照。实际微信云端、手机触控、微信无障碍及真机键盘需实施阶段验证。

- 管理表单输入保护：处理原因未提交时，切换筛选、改选其他成员或取消编辑均先确认放弃；取消确认保留原因，同一成员重复点击不重置。离开页使用微信原生提醒，处理失败保留输入。复用第28页未保存离开状态，不增加业务规则。
